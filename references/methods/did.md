# DID / 事件研究（一页）

用于 `identification-audit` / `robustness-checklist` / `referee-sim`。事件研究默认是 DID 的图和诊断，不是第二种贡献。

## 先问（不定下来不准写主回归）

1. 处理是同一天开始，还是错时进入？
2. 处理发生在哪一层（省 / 市 / 企业 / 债券）？聚类是否对这一层？
3. 对照是谁：从未处理、尚未处理，还是已经处理过的？
4. 有没有预期（政策公布早于生效）？

## 决策树

```
所有处理组同一时点进入？
├── 是（经典 2×2）
│   └── 双向固定效应可以当起点；仍要事件研究 / 事前系数
└── 否（错时）
    └── 不要只报传统 TWFE
        写清用了哪种估计量（如 CS、Sun-Abraham、BJS、dCdH 等）
        至少再报一种，或写明为何只有一种适用
        对照是「尚未处理」还是「从未处理」必须说清
```

组间处理强度不同、连续处理、开关多次：先承认 TWFE 更难解释，再选估计量。不确定就停，列选项问用户。

## 最危险的三件事

1. 错时样本上只报 TWFE，加权可能为负，符号能反
2. 事前系数已经动，还把主结果写成因果
3. 聚类在个体，处理在地区——标准误讲的是另一个实验

## 必须先做

- 事件研究图（事前系数看得到）
- 错时：现代估计量或「为何仍用 TWFE」的书面理由
- 处理定义、样本进出（谁在处理前消失）
- 安慰剂时点或安慰剂结果（至少计划一项）
- 聚类 = 处理赋值层级

## 代码提示

Stata 常见：`csdid`、`eventstudyinteract`、`did_multiplegt`、`reghdfe`（仅当设计真是 2×2 或用户显式接受 TWFE）。语法查 stata-skill；默认策略查 [EconAgentSkills](https://github.com/JonasWeinert/EconAgentSkills) 的 DID 树，不要把上游全文贴进 memo。

## 写作边界

事件研究、分组、安慰剂 = 防守。禁止「此外我们还发现…」做成第二条贡献。没有平行趋势故事，就不要写「政策导致」。
