# IV（一页）

用于 `identification-audit` / `robustness-checklist` / `referee-sim`。

## 先问（不定下来不准写第二阶段）

1. 工具通过什么制度/地理/历史渠道碰到处理，又不该直接碰结果？
2. Estimand 是对谁：合规者 LATE，还是被写成 ATE？
3. 一阶段会弱吗？弱的时候准备用哪套推断，而不是只看「F>10」口头禅
4. 聚类对上处理/工具赋值的层级了吗？

## 决策树

```
工具 → 处理 的通道是否说得清？
├── 否 → 先写制度故事，不准先跑 2SLS
└── 是
    ├── 一阶段弱 → 报弱 IV 稳健程序；不要只报普通 2SLS 当主结果
    └── 一阶段不弱
        ├── 排他：列出「若排他错，估计会歪向哪」的可证伪含义
        └── 多个工具：过度识别；约简式与 2SLS 同向吗？
```

排他限制不能靠「我们认为」。至少写一条：换结果、换样本、或制度上不该存在的约简式，用来打自己。

## 最危险的三件事

1. 工具走旁路（直接进结果，或只通过另一个未观察处理）
2. 弱工具把 2SLS 吹成显著因果
3. 把 LATE 写成「对所有人」

## 必须先做

- 一阶段（系数 + 弱工具统计，F 或等价物）
- 弱时：弱 IV 稳健推断或明确降级表述
- 约简式（工具 → 结果）与 2SLS 是否同向
- 排他的可证伪含义（写在 memo 里，不是空话）
- 多个工具才谈过度识别；一个工具不要假装做过 Hansen

## 代码提示

Stata 常见：`ivreg2`、`ivregress`、弱 IV 相关选项。语法查 [stata-skill](https://github.com/dylantmoore/stata-skill)。现代默认（不要只喊 F>10）对照 [EconAgentSkills](https://github.com/JonasWeinert/EconAgentSkills)。

## 写作边界

只允许讲清合规者、工具触达的人群。机制段落若只是「工具显著所以机制成立」，判 overclaim。
