# robustness-checklist

稳健性是防守清单，不是新结果工厂。

## 步骤

1. 确认方法家族。混合设计就按主识别列主清单，次设计单列一小节。
2. 输出三类：`必须做` / `建议做` / `不要做成贡献的东西`。
3. 若用户给了 `tables/`、`code/` 或卡片：逐项标 `已做` / `未做` / `做了但文中未写`。没给文件则全表为「待对照」。
4. 每项写清：检验什么假设、拒绝时估计还能否当因果讲。
5. 默认写入 `memos/YYYY-MM-DD-<slug>-robustness.md`。

## 按方法的必须项（可增补，不可删到低于这个）

**RD**

- 排序变量密度 / McCrary 或等价操纵检验
- 切断点处协变量平衡
- 带宽敏感（含最优带宽两侧）
- 核与多项式阶
- donut（去掉切断点附近）
- 若模糊 RD：一阶段与合规者解释

**DID**

- 事件研究 / 事前系数
- 错时处理：不要只报传统 TWFE；写清用了哪种估计量或为何不适用
- 处理定义与样本进出
- 安慰剂处理日或安慰剂结果
- 聚类与处理层级一致

**IV**

- 一阶段（系数、F 或等价弱工具统计）
- 弱 IV 程序（若 F 不高）
- 排他限制的可证伪含义（不是空口「我们认为」）
- 过度识别（若有多个工具）
- 2SLS 与约简式是否同向

**事件研究**

- 事前系数图 + 联合检验（若做了就报告，没做标未做）
- 窗口与端点 bin 敏感
- 预期效应的制度故事是否与事前系数一致
- 事件发生层级的聚类

**调节 / GVC 类交互**

- 交互项 estimand 的文字定义（对谁、相对谁）
- 调节变量是否可能被处理影响
- 分组回归或三重交互是否改变结论
- 禁止：只因为交互显著就写成「机制是全球价值链」

## 禁止

- 把每一项稳健性改写成「此外我们还发现」
- 列出与识别无关的厨余回归冒充严谨
- 编造用户没跑过的系数来填「已做」
